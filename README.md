# HH4YOU — Умный подбор вакансий и генератор сопроводительных писем на базе ИИ 🎯

[![Playwright Tests](https://img.shields.io/badge/tests-Playwright-brightgreen.svg?logo=playwright)](https://playwright.dev/)
[![Node.js Version](https://img.shields.io/badge/node-%3E%3D20.0.0-blue.svg?logo=nodedotjs)](https://nodejs.org/)
[![Database](https://img.shields.io/badge/database-Postgres%20%7C%20SQLite-blue.svg?logo=postgresql)](https://www.postgresql.org/)
[![LLM Backend](https://img.shields.io/badge/AI-OpenAI%20%2F%20Ollama-orange.svg?logo=openai)](https://openai.com/)

**HH4YOU** — это полнофункциональный автоматизированный помощник по поиску работы, разработанный для исключения рутинного ручного труда при поиске и сопоставлении вакансий, составлении персонализированных сопроводительных писем.

Приложение периодически сканирует популярные российские платформы для поиска работы (**HeadHunter**, **Хабр Карьера** и **SuperJob**), обрабатывает полученные вакансии с помощью **LLM** для сравнения их с резюме пользователя, оценивает степень соответствия (0-100%), составляет индивидуальные сопроводительные письма и мгновенно отправляет уведомления по электронной почте о наиболее подходящих вакансиях.

## 🧪 Инфраструктура автоматизации тестирования и QA (Избранное портфолио)

Проект содержит автотесты, написанные на **TypeScript** с использованием **Playwright**. Тесты структурированы так, чтобы продемонстрировать лучшие практики QA и чистые паттерны автоматизации.

### 📁 Структура папки тестов
```
e2e/
├── api-clients/     # Программные обертки для проверок API и быстрой подготовки тестов
├── data/            # Динамические генераторы тестовых данных и шаблоны резюме (Фабрики)
├── fixtures/        # Переопределения тестов Playwright и контроллеры сидинга базы данных
├── pages/           # Реализация паттерна Page Object Model (POM) для экранов UI
└── tests/
    ├── api/         # Интеграционные тесты ключевых эндпоинтов API
    └── ui/          # Сквозные пользовательские сценарии и тесты визуального регресса
```

### 🛠️ Ключевые практики тестирования и паттерны проектирования

1. **Паттерн Page Object Model (POM):**
   Все селекторы UI и действия пользователей отделены от логики тестов. Тесты интерфейса используют семантические локаторы, определенные в `e2e/pages/` (например, [auth-modal.page.ts](file:///d:/Projects/HH4ME/e2e/pages/auth-modal.page.ts) или [dashboard.page.ts](file:///d:/Projects/HH4ME/e2e/pages/dashboard.page.ts)), что упрощает поддержку.
   
2. **Прямое наполнение базы данных (`db-seeder.ts`):**
   Для обхода сложных или медленных процессов регистрации пользователей и оплаты во время тестирования [DbSeeder](file:///d:/Projects/HH4ME/e2e/fixtures/db-seeder.ts) устанавливает прямое подключение к SQLite. Это позволяет:
   - Программно создавать учетные записи.
   - Напрямую активировать подписки в базе данных (в обход формы оплаты YooKassa).
   - Быстро сбрасывать состояние базы (`clearTestUsers`) в хуках `beforeEach`/`afterEach` для изоляции тестов.

3. **Многоуровневое тестирование API и API-клиенты:**
   Вместо использования стандартных сырых запросов fetch в тестах API применяются структурированные HTTP-клиенты (например, [auth.client.ts](file:///d:/Projects/HH4ME/e2e/api-clients/auth.client.ts)). Они выполняют двойную роль: напрямую тестируют REST-эндпоинты и позволяют быстро авторизовывать UI-тесты без прохождения графических экранов входа.

4. **Визуальный регресс (Тестирование скриншотами):**
   Использует инструменты визуального сравнения Playwright (`visual-regression.spec.ts`) для проверки рендеринга интерфейса на различных разрешениях экранов (viewport), предотвращая съезжание верстки и визуальные регрессы в адаптивных представлениях.

5. **Параллельное выполнение тестов и оптимизация БД:**
   Подключение к SQLite в режиме тестирования настроено с включенным режимом **Write-Ahead Logging (WAL)** и строгими таймаутами ожидания (`busyTimeout`), что позволяет параллельно запускать воркеры Playwright без блокировки базы данных (`database is locked`).

## 🚀 Технологический стек

### Бэкенд
* **Среда выполнения:** Node.js (v20+)
* **Фреймворк:** Express.js
* **База данных:** SQLite (для разработки и локальных интеграционных тестов) и PostgreSQL (для продакшна)
* **ИИ-движок:** OpenAI-совместимая обертка API (по умолчанию `gpt-4o-mini`; легко заменяется на локальные модели через Ollama, OpenRouter или Sber GigaChat)
* **Авторизация и безопасность:** JWT (JSON Web Tokens), `cookie-parser`, хеширование паролей с помощью `bcryptjs` и ограничение частоты запросов с использованием `express-rate-limit`
* **Движок парсинга:** Cheerio (парсинг HTML), Axios (HTTP-запросы с механизмами повторных попыток и ограничением частоты)
* **Уведомления:** Email-уведомления по протоколу SMTP с помощью Nodemailer
* **Платежи:** Интеграция с API YooKassa для ежемесячных подписок

### Фронтенд
* **UI Structure:** Одностраничное приложение (SPA) на чистом HTML5 / JavaScript (ES6)
* **Стилизация:** Чистый CSS (с современной темной темой, стеклянными элементами интерфейса (glassmorphism), переходами и адаптивной версткой)
* **Ресурсы:** Иконки Boxicons, шрифты Google Fonts (Inter, Manrope)

## ⚙️ Конфигурация и окружение

Настройки приложения управляются с помощью переменных окружения. Скопируйте шаблон и заполните его своими ключами:

```bash
cp .env.example .env
```

Ключевые свойства окружения:
* `DATABASE_URL`: Строка подключения к PostgreSQL (для продакшна).
* `DB_TYPE`: Установите значение `sqlite` для легкой локальной разработки и автоматического E2E-тестирования.
* `LLM_BASE_URL` и `LLM_API_KEY`: Настройки API, OpenRouter, Sber GigaChat (`https://api.giga.chat/v1`) или локального инстанса Ollama (`http://localhost:11434/v1`).
* `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`: Параметры исходящей почты для отправки уведомлений в реальном времени.
* `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`: Учетные данные YooKassa для тестовых или реальных платежей.

## 🏁 Начало работы

### Требования
* Node.js v20 или выше
* npm v10 или выше
* (Опционально) Docker

### 1. Установка
Клонируйте репозиторий и установите зависимости разработки и продакшна:
```bash
npm install
```

### 2. Запуск приложения локально
Запустите Express-сервер и фоновый планировщик задач (worker):
```bash
npm start
```
По умолчанию сервер запускается на [http://localhost:8000](http://localhost:8000).

## 🧪 Запуск автотестов

Все тесты запускаются на локальной базе данных SQLite, которая автоматически настраивается средствами конфигурации локального сервера Playwright.

| Команда | Описание |
| :--- | :--- |
| **`npm run test:e2e`** | Запускает весь тестовый пакет E2E (тесты API и UI) |
| **`npm run test:ui`** | Запускает только графические тесты UI (разрешения для ПК и мобильных) |
| **`npm run test:api`** | Запускает только интеграционные тесты API бэкенда |
| **`npm run test:report`** | Открывает отчет HTML для анализа результатов тестирования, логов трассировки и видеозаписей |

### Особенности запуска тестов
* **Повторные попытки (Retries):** Настроены для автоматического перезапуска упавших тестов в режиме CI.
* **Артефакты:** Автоматическое сохранение скриншотов, сетевых логов и видеозаписей сессий при сбое теста.
* **Параллельное выполнение:** Использование преимуществ многоядерных процессоров для одновременного запуска независимых тестов.
